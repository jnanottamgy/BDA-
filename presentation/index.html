Scalable Analysis of Hourly Air Quality Data from Indian Monitoring Stations Using Apache PySpark

Harshavardha Satish Kumar · 1MS24CS065
Guide: Uzma Sultana

Problem

CPCB stations log PM2.5, PM10, NO₂, SO₂, CO and O₃ every hour, producing millions of readings. We need a scalable way to find when, where and how pollution changes.

Q1 Peak months, seasons and hours
Q2 Most polluted cities and stations
Q3 AQI category distribution
Q4 Effect of the 2020 lockdown
Q5 Data completeness
Q6 PySpark vs Pandas runtime

Base paper

Bogomolov & Plotnikov (2024). The possibilities of using Big Data technologies in processing atmospheric air pollution data. Computational Nanotechnology 11(1).

They did
PySpark processing model for gas-analysis station data; Pandas vs PySpark comparison
Gap
Results tied to their own data and hardware; no public Indian dataset
We do
A reproducible pipeline on public CPCB data with documented cleaning and a defined test setup

Architecture

CSV (explicit schema)→Clean: dedup, types, range checks→Join stations (broadcast)→Features: year, month, hour, season→Parquet (partitioned by year)→Spark SQL / DataFrame aggregates→Charts + Pandas benchmark

PySpark local[*] · Spark SQL · Parquet · Pandas baseline · Matplotlib/Seaborn

Data quality

Rows before / after cleaning, duplicates removed, and per-pollutant completeness come from output/data_quality.json
Rules
• Remove duplicate (station, time) rows
• Set out-of-range values to null
• Keep rows that have PM2.5 or PM10
